## Unattended interface
- For JSON payloads sent to broker/helper commands, never reuse a fixed temporary filename such as `checkpoint-irrelevant.json`. Use a new unique path for every payload, or read an existing file before overwriting it. This prevents internal file-write warnings from leaking into scheduled family messages. Resolve any tool failure before finalizing; user-facing output must contain only the useful family summary or `[SILENT]`.
- `automation_status`: authorized mailbox, counts, approved destination, lease duration.
- `automation_poll --max 10 [--page-token TOKEN]`: claims unread, unprocessed messages for 60 minutes. Returns message IDs, per-message leases, next_page_token. No search query override. Gmail UNREAD is never changed. Follow pagination even when a page has no claimed messages; previously completed unread messages still occupy pages. Bound each run to 50 messages / 10 minutes, finish or release claimed messages, and discard the page token at the end of the current run. If a saved page token is rejected, restart from the first page; processed IDs still deduplicate. Once pagination finishes, begin at the first page on the next scheduled run for new mail.
- `automation_get ID --lease LEASE`: message bodies, attachment descriptors and saved progress. Body truncation is explicit; retrieve a text attachment when Gmail stored a body externally. Leases are opaque workflow handles, not Gmail tokens.
- `automation_attachment ID --lease LEASE --part-id PART`: base64url content of an attachment belonging to that message, up to 10 MB. For agenda PDFs, use agenda_pdf.py and keep the file until scheduled delivery is confirmed. For other attachments, use private temporary files and safe readers, then remove them when no longer needed. Do not print base64 into chat. Unsupported/large files require review; do not pretend they were read.
- `automation_checkpoint ID --lease LEASE --step classification|calendar|tasks|summary` with a small JSON value on stdin: stores durable progress/results (IDs, not email bodies).
- `automation_ack ID --lease LEASE`: mark processing complete in the broker, not Gmail. Repeat ack is safe. Completed messages are never claimed again.
- `automation_release ID --lease LEASE`: retry later, retaining checkpoints. A crash allows re-claim after lease expiry. Do not ack on failed/partial work.
